# 架构与操作边界

## 服务

emmc-web.service 以 emmc-web 普通用户运行 Flask/Waitress，监听 80 端口，仅拥有 CAP_NET_BIND_SERVICE。前端在电脑或 CI 构建，设备不运行 Node.js。

emmc-worker.service 以 root 运行固定操作工作进程。Unix socket 的目录权限及用户组限制访问，Web 服务通过该接口发起经过校验的操作。不开放任意 shell，外部命令使用参数数组执行。

Web 与工作进程状态分开存放。密码采用随机盐和 scrypt 单向哈希，文件权限 0600；生产依赖由 apt 安装，开发依赖使用 requirements-dev.txt。

## 磁盘操作

系统根目录和 /boot 所在磁盘受保护。写入前重新核对身份、容量、区域和占用，同一磁盘修改互斥。有外部挂载、swap、holders 或使用者时拒绝写入，不强制卸载。

文件默认只读，编辑短暂挂载并限定在分区内，阻止路径越界与符号链接逃逸。分区表和字节修改前保存快照。BOOT 写入仅临时解除软件只读，结束后恢复；RPMB 仅展示，不提供密钥或永久配置写入。

只支持 ext4 调整，起点固定。源目标同盘/重叠、容量不足或身份变化会拒绝。任务持久化，重启标记中断，不自动续写。失败或取消不会自动回退已经覆盖的内容。

## 下载与备份

直接下载通过有界 Unix socket 数据帧与 HTTP 流式返回浏览器，缓冲不随镜像增长。备份在传输中打包压缩，最后写入 SHA-256 清单，不在 SD 暂存镜像。

SD/USB 备份保存镜像和清单。完整备份包含用户区、BOOT0、BOOT1，不包含 RPMB 密钥。恢复前检查清单和容量，完成后读回校验，不自动修改 EXT_CSD 启动配置。

## 发布

仓库包含源码、测试、文档和可公开截图，不发布运行日志、状态文件、密钥、数据库和设备验收捕获。发布打包使用明确文件清单，包含 backend、dist、deploy、README、VERSION。

安装器检测任务与端口，关闭 Web 接收后复查，再替换程序。状态目录保留，成功更新留存旧程序副本；失败时尝试恢复。下载验证 SHA-256，并拒绝归档越界路径和链接。

## 独立升级服务

emmc-updater.service 从 root 管理的 `/usr/local/lib/emmc-studio-updater` 运行，升级状态写入 `/var/lib/emmc-updater`。受限 Unix socket 仅开放状态、官方版本检测和签名包安装三种操作；Web 保留登录与 CSRF 保护，CLI 要求 root。签名校验公钥不读取上传内容，拒绝降级、链接和越界路径。

升级器通过具有 root 对端身份验证的 worker 维护接口原子冻结磁盘任务准入，检查全部历史中的活动状态和占用锁；新启动 worker 也检查 root 管理的维护标记。安装器不重启升级服务，因此 Web/worker 重启期间仍持续执行和保存升级状态。结束后解除维护锁并清理此次升级暂存，程序安装失败尝试回滚。断电或服务重启记录中断，不自动继续安装。
