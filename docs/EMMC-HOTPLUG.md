# eMMC 换片检测

读卡器的 eMMC 控制器需要按可移除介质处理。原设备树的 `non-removable`
会使内核只做首次扫描；专用配置移除它并加入 `broken-cd`，通过 MMC 核心轮询检测拔出和插入。
默认保留原 DTB 的速度配置；显式使用 `--compatible` 的试验配置将最高频率限制为 52 MHz，移除 HS200/HS400、增强选通和 DDR 模式，
改用普通 MMC 高速模式，并将初始化等待时间设为 200 毫秒。
这是为当前控制器的反复换片问题采用的兼容方案，会降低峰值传输速度；
轮询和降速配置本身不能代替实际换片验收。
没有修改系统 SD 卡控制器、eMMC 数据、BOOT 区或 RPMB。

## 首次启用

适用于从 SD 卡运行 Armbian、使用单个 8 位 MMC 控制器连接可更换 eMMC 的设备。
先结束磁盘任务，并安全卸载 eMMC：

```bash
sudo apt-get install device-tree-compiler
sudo python3 deploy/configure-emmc-hotplug.py
sudo reboot
```

脚本按系统拓扑查找控制器，拒绝修改挂载中的 eMMC，并验证新 DTB 可解析。
原 DTB 和 `armbianEnv.txt` 保存在脚本输出的备份目录中；不覆盖原厂 DTB。
首次切换设备树需要一次重启；之后内核自动检测，网页每 3 秒刷新一次。
磁盘概览显示“热插拔检测已启用”表示当前内核已加载轮询配置。

## 更换

结束传输、克隆、恢复和编辑任务，并卸载文件系统后更换芯片。
新芯片出现时，网页按 CID 和内核 `diskseq` 区分介质，切回 eMMC 并清空旧扇区预览、编辑草稿与操作对话框。
即使设备路径相同，旧挂载缓存也不能复用到新介质。读卡座和接线必须支持实际带电更换。

分区表读取超过 3 秒时会跳过本次查询，避免损坏介质拖住整个设备列表。
失败查询等待 30 秒后重试；新 CID 或新 `diskseq` 可立即重新查询。
此时仍显示内核识别到的容量和区域，但不能将缺失的分区表信息理解为磁盘为空。

若未重新出现，查看：

```bash
lsblk
dmesg | tail -60
```

## 回退

恢复脚本输出的备份 `armbianEnv.txt` 后重启。
如果修改前已经使用同名 `emmc-studio-hotplug.dtb`，还需将输出的 `rollback_dtb`
复制回修改前的 DTB 路径（当前为 `/boot/dtb/rockchip/emmc-studio-hotplug.dtb`），
再执行 `sync` 和重启；只恢复环境文件不能回退同名 DTB 的内容。
专用 DTB 是原内核 DTB 的副本；升级内核后应先恢复该内核对应的原厂 `fdtfile`，
再重新执行配置脚本，避免混用旧内核 DTB。

## 本机验证

2026-10-04 在 NanoPi R28S 上启用后，实际更换芯片无需再次重启：
BJTD4R（31,268,536,320 字节）被移除后，H8G4a（7,818,182,656 字节）自动出现，
内核重新枚举用户区、两个分区、BOOT0、BOOT1 和 RPMB。
用户区与两个 BOOT 区各读取 64 字节成功，BOOT 区 `force_ro` 均保持为 `1`。
网页认证接口与工作进程正常；没有为验证写入芯片数据。
该验证适用于当前设备及读卡连接，其他硬件需要独立验证供电和连接条件。

随后换回 BJTD4R 时，内核检测到 H8G4a 拔出，但出现持续的
`Card stuck being busy! __mmc_poll_for_busy`，尚未完成反向换片识别。
因此当前不能认定所有芯片均可稳定反复热插拔；需要继续验证插座接触、供电复位及控制器初始化。
拔出等待后重新插入，以及仅解绑、重新绑定 eMMC 控制器，均未恢复这次识别。
当前设备树未配置该控制器的 `vmmc-supply` / `vqmmc-supply`，
不能将软件重新扫描视为已对芯片完成断电复位。

再次插入 H8G4a 后，无需重启即重新出现（`diskseq=20`），两个分区与
BOOT0/BOOT1 重新枚举，三个普通存储区域各读取 64 字节成功。
这一次对照中重新扫描恢复识别 H8G4a，但尚不能认定问题只影响 BJTD4R。
随后再次切换，连续两次设备查询均只显示系统 SD 卡，内核再次持续报忙状态超时，
确认该初始化失败可重复出现，不能将当前实现视为所有芯片的热插拔验收通过。
继续执行一次软件重启后，等待约 60 秒仍只识别系统 SD 卡；eMMC 控制器驱动已加载，
网页及工作进程正常。软件重启未恢复这次芯片识别，尚需实际断电再上电的对照验证。

后续用户再次重启后，实测 H8G4a 在启动约 8.8 秒时完成 HS400 枚举，
用户区、BOOT0/BOOT1 与 RPMB 重新出现。因此不能将初始化失败归因于特定芯片型号。
当前只完成内核轮询和网页介质变化处理，反复换片仍存在需要重启才能恢复的情况，
完整热插拔尚未验收通过。没有可控电源节点的日志只能证明缺少这项配置，不能证明故障根因。

随后部署了 52 MHz 兼容配置，实测 H8G4a 以普通高速模式启动，实际时钟 50 MHz；
内核明确打印 `Disabling HS200/HS400`。三个普通存储区域只读验证通过，
所有其他设备树节点与修改前一致。兼容配置下实际换片仍出现忙状态超时，未解决问题。
命令跟踪显示 CMD1 正常完成（`cmd_err=0`），持续响应 `0x40ff8080`，就绪位未置位。
随后按用户要求恢复修改前的 200 MHz HS400 配置，保留内核轮询；不再默认使用降速方案。
